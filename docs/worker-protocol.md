# TypeScript worker protocol (v1)

The .NET host starts `node worker/dist/main.js` once per request, writes one JSON document to stdin and reads one JSON document from stdout. Diagnostics go to stderr. Exit code 0 on success (even when analysis facts contain failures); non-zero only for crashes or malformed requests. The JSON shapes mirror the C# records in `src/CodeShield.Abstractions` (camelCase property names). **All paths are repository-relative with forward slashes** (`src/a/b.ts`).

## Request

```json
{
  "protocol": 1,
  "command": "analyze",            // or "tokenize"
  "root": "C:\\abs\\snapshot\\root",
  "files": ["package.json", "tsconfig.json", "api.ts"],   // every repository file in this snapshot (tracked + untracked non-ignored); never walk the disk for the inventory
  "focusFiles": ["api.ts"],        // changed supported source files, expressed in this snapshot's paths
  "changedConfigFiles": [],        // changed tsconfig*.json / package.json paths in this snapshot
  "isBaseline": false,
  "correctnessRules": [            // from the .NET catalog (single source of truth)
    { "analyzerId": "@typescript-eslint/no-floating-promises", "evaluatorId": "correctness.typescript.no-floating-promises", "options": [{ "ignoreVoid": false }] }
  ]
}
```

`tokenize` requests carry `root` and `files` (source files to tokenize) only.

## analyze response (`LanguageAnalysis`)

```json
{
  "language": "typescript",
  "analyzerVersions": { "typescript": "5.9.3", "eslint": "9.x", "typescript-eslint": "8.x", "node": "22.x" },
  "contexts": [ ContextFacts ],
  "graph": ModuleGraphFacts,
  "inputs": [ { "scope": "repository|external", "path": "...", "sha256": "..." } ],
  "unownedFiles": [ "focus files with no owning tsconfig" ],
  "failures": [ Reason ]
}
```

* `inputs`: every file the analysis read (sources, tsconfig/extended configs, package.json, lib/`node_modules` typings, etc.). Hash the **bytes you actually used** at read time (wrap the compiler host `readFile`/`getSourceFile`, or read through a helper that hashes). Repository files: `scope=repository` and repo-relative path. Files outside the snapshot root (including `node_modules` realpaths outside it and TypeScript's own `lib.*.d.ts`): `scope=external`, canonical absolute path with forward slashes.
* `unownedFiles` and per-file/per-rule failures use the reason codes in `docs/specification.md` (`UNRESOLVED_OWNERSHIP`, `MISSING_DEPENDENCY`, `PROJECT_LOAD_FAILED`, `MISSING_ANALYZER`, `SUPPRESSED_RULE`).

### ContextFacts (one per standalone tsconfig that owns at least one focus file or whose config chain/package changed)

* `contextId`: the tsconfig path (repo-relative). `configPath`: same. `framework`: null. `language`: `typescript`.
* `modulePath`: path of the nearest ancestor `package.json` (within the repository, from `files`) of the tsconfig directory-owning file set... **module ownership is per source file** (nearest ancestor `package.json` of the file); a context's `modulePath` is the package.json of the tsconfig's directory's nearest ancestor package.json (null if none → add a failure `UNRESOLVED_OWNERSHIP`).
* `ownedFiles`: every source file the tsconfig includes (resolved with TypeScript's `files/include/exclude/extends/references` rules through `ts.parseJsonConfigFileContent`), excluding `.d.ts`, `node_modules`, and generated build output. Exclude a tsconfig from standalone analysis when another config extends it and no TS project reference points to it (still use it as a settings source for its extenders).
* `files`: `FileFact` for each owned **focus** file only. `codeLines` counts physical lines containing at least one token that is not a comment or whitespace (a multi-line token counts every line it spans). `generated`: true for `*.generated.ts`, `*.g.ts`, or a file whose first lines contain `@generated`/`<auto-generated>`. `methods`: one `MethodFact` per executable function with a body (function declarations, methods, constructors, get/set accessors, arrow functions, function expressions; overload signatures without bodies are skipped).
* `classes`: `ClassFact` for classes declared in focus files (LCOM4, see below); `types`: `TypeFact` for **every** class and interface declared in every owned non-declaration source file (`isAbstract` = `abstract class` or interface; skip type aliases/enums). `unitId` = `<file>#<Qualified.Name>`.
* `diagnostics`: ESLint results (flat config, `@typescript-eslint/parser` with `parserOptions.project` = this tsconfig, only the requested rules with the given options, `reportUnusedDisableDirectives: off`, `noInlineConfig: true` so repository `eslint-disable` comments and repo ESLint config do not affect it; `linterOptions.noInlineConfig` — **if the file contains an `eslint-disable` comment naming a selected rule (or a blanket one), add a failure `SUPPRESSED_RULE` for that rule** instead of silently passing). Lint every owned file for the context (not only focus files). `analyzerId` = the full ESLint rule id, `unitId` = `<file>#<enclosing function/class qualified name>` or `<file>#<module>`.
* `failures`: `Reason` entries with `ruleId` = **evaluator rule id** (e.g. `correctness.typescript.no-floating-promises`, `cohesion.lcom4`, or a method metric id) and a context id; for example type information unavailable (`MISSING_DEPENDENCY`), tsconfig parse error (`PROJECT_LOAD_FAILED`, ruleId null = all rules for the context).

### Measurement rules (must match the spec exactly; see `docs/specification.md` "Shared measurement rules")

* Complexity: start 1; +1 per `if` (incl. else-if), `for`, `for..of`, `for..in`, `while`, `do..while`, `catch`, conditional `?:`, non-default `case`; +1 per `&&`, `||`, `??`, `??=` anywhere in the body. `default` clause: 0. Nested functions are separate units; their decisions do not count in the enclosing function. `decisions` evidence: `{ "decisionKind": "if|loop|catch|conditional|case|logical", "line": N }`.
* Nesting: body depth 0; entering the body of an if/loop/switch/catch or a branch of `?:` adds one; `else if` is at the same depth as its `if`; `else` body is at the same depth as the `if` body; switch cases add nothing beyond the switch; try/finally/plain blocks add nothing; max depth reached; nested functions measured separately. `nestingPoints`: `{ constructKind, line, depth }` for each depth-introducing construct (depth = the depth of its body).
* `codeLines` (method): physical lines with a non-comment token from the declaration start (decorators/modifiers included) through the end of the body; nested function text counts toward the enclosing function. `parameterCount`: declared parameters, excluding the TypeScript `this` pseudo-parameter; a destructured parameter counts once; optional/rest count.
* Names: `unitId` = `<file>#<Qualified.Name>` (class members `Class.method`, nested `outer.<inner>@<line>`, anonymous `<anonymous>@<line>`); `name` = short readable name; `span` covers the function including the signature (1-based lines/columns, end inclusive-of-last-character+1 is fine; be consistent).
* LCOM4 (`ClassFact`): nodes = concrete instance methods and accessors with bodies (exclude constructors, static members, empty bodies, abstract/overload-only members); instance state = declared instance property declarations and fields, and constructor parameter properties; edges when two nodes access the same declared own instance field/property via `this.x` (resolved by symbol with the type checker, not by text) or when one directly calls the other via `this.m()`; no edges from code inside nested functions; inherited and static members ignored. Applicable only when there is instance state and at least two nodes. `components` = connected components (lists of node ids). `edges[].reason` = `field:<name>` or `call`. `locations`: file + span of the class declaration.
* Duplicated fields must be deterministic: sort all arrays by (path, line, column, name) ordinal.

### Module graph (`graph`)

Repository-wide, independent of focus: `modules` = every `package.json` path in `files`. For each non-declaration TS/TSX/MTS/CTS source file in `files` (outside `node_modules`), scan imports/exports/dynamic `import()`/`require` with `ts.preProcessFile`, resolve with `ts.resolveModuleName` using the compiler options of the nearest tsconfig (defaults if none) and the real file system under `root`. Resolved targets inside the repository (realpath, not in `node_modules`) produce:

* `fileImports` (`from`,`to`,`typeOnly`) for every resolved repository-file edge;
* `edges` (`from`,`to` = package.json paths, `typeOnly` = true only if **all** imports behind that edge are type-only) for edges between different packages (deduplicated per pair).

Imports that look relative or workspace-internal but cannot be resolved produce `unresolved` entries (`MISSING_DEPENDENCY`, contextId = importing file). Bare third-party specifiers that resolve into `node_modules` or are simply not installed are not errors.

## tokenize response (`TokenizeResult`)

`{ "files": [ { "path": "...", "tokens": [ { "kind": "Identifier", "text": "x", "line": 1, "column": 1, "endLine": 1, "endColumn": 2, "offset": 0 } ] } ], "failures": [] }` — TypeScript scanner tokens, comments/whitespace/trivia excluded, exact text and syntax kind name retained (`ts.SyntaxKind[kind]`), 1-based lines/columns, `offset` = start offset. Template literals and regex tokens must be scanned correctly (use `ts.createSourceFile` and walk tokens rather than a raw scanner when context-sensitive).

## Packaging

`worker/package.json` pins exact versions (no ranges) of `typescript`, `eslint`, `typescript-eslint` (and `@types/node`); `package-lock.json` is committed; setup runs `npm ci && npm run build` (compiles `src/*.ts` to `dist/`). No network access or install at analysis time. `main.js` prints the JSON response only on stdout.
